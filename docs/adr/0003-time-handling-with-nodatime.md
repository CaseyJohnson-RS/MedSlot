# 0003. Работа со временем через NodaTime

- **Статус:** Принято
- **Дата:** 2026-10-30

## Контекст

Расписание врача задаётся в локальном времени («пн 9:00–18:00»), а записи — конкретные моменты. `DateTime` и `DateTimeOffset` не различают «момент» и «время на часах», легко теряют `Kind` и плохо справляются с переходами на летнее/зимнее время. Правила домена (N часов до приёма, окно нарушений) завязаны на текущее время, и их нужно тестировать.

## Решение

- Используется NodaTime: `Instant` для моментов, `LocalDate` / `LocalTime` для расписания, `DateTimeZone` клиники для преобразований.
- В БД — `timestamptz` (UTC), маппинг через `Npgsql.NodaTime`.
- Текущее время — только через `IClock`; в тестах — `FakeClock`.
- Локальное → UTC через `Resolvers.LenientResolver` (правила в [domain.md, §4](../domain.md#4-время)).
- Domain-сборка может зависеть от NodaTime — единственное исключение из правила «Domain зависит только от BCL», закреплённое в архитектурных тестах.

## Рассмотренные варианты

- **`DateTimeOffset` + `TimeProvider`.** Без доп. зависимостей, но нет типов для локального времени и явной обработки DST. Отклонено.
- **Хранить расписание в UTC.** Ломается при смене смещения. Отклонено.

## Последствия

- Явные типы исключают путаницу «момент / время на часах».
- Все тесты, зависящие от времени, детерминированы.
- Нужны конвертеры для EF Core, System.Text.Json (`NodaTime.Serialization.SystemTextJson`) и OpenAPI-схемы.
