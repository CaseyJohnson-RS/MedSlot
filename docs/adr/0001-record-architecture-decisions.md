# 0001. Фиксировать архитектурные решения в ADR

- **Статус:** Принято
- **Дата:** 2026-10-30

## Контекст

В проекте много неочевидных решений: свой outbox, exclusion constraint, отказ от MediatR. Без записи причин через месяц непонятно, почему сделано именно так, а читателю репозитория — тем более.

## Решение

Каждое архитектурно значимое решение оформляется как ADR в `docs/adr/` по шаблону [template.md](template.md). Номера сквозные, файлы не переписываются: изменённое решение — новый ADR со статусом «Заменяет NNNN».

## Последствия

- Решение принимается с явным контекстом и альтернативами.
- Технология или библиотека добавляется в стек только вместе с ADR.
