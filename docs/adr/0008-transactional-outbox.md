# 0008. Transactional Outbox своими руками

- **Статус:** Принято
- **Дата:** 2026-10-30

## Контекст

После записи к врачу событие `AppointmentBooked` должно попасть в Kafka: по нему работают уведомления, аналитика, аудит. Если сохранить запись в Postgres и затем отправить событие в Kafka, то между этими шагами процесс может упасть, Kafka может быть недоступна или транзакция откатится уже после отправки. Получим запись без события или событие без записи. Распределённой транзакции между Postgres и Kafka нет.

MassTransit, где outbox есть из коробки, с 2025 года коммерческий (см. README). Кроме того, outbox — один из центральных механизмов проекта, и его полезно понимать до деталей.

## Решение

**Запись.** `DomainEventsToOutboxInterceptor` перед `SaveChanges` собирает доменные события всех отслеживаемых агрегатов, превращает их в интеграционные события (`IntegrationEventMapper` → контракты из `MedSlot.Contracts`) и добавляет строки в `outbox_messages`. Они вставляются тем же `SaveChanges`, одной транзакцией с изменением. Событие существует тогда и только тогда, когда изменение сохранено.

**Публикация.** `OutboxRelay` (фоновая служба в API):
- выбирает неопубликованные строки по возрастанию `id` (частичный индекс `WHERE published_at IS NULL`);
- публикует по одной, дожидаясь подтверждения брокера (`acks=all`, идемпотентный продюсер);
- после подтверждения ставит `published_at`, при ошибке увеличивает `attempts` и сохраняет `last_error`;
- активен один экземпляр на систему, правила порядка — в ADR 0009;
- при ошибках делает экспоненциальную паузу до 30 с; опубликованные события старше 7 дней удаляет.

**Контракты.** Отдельный проект `MedSlot.Contracts` без зависимостей содержит конверт (`EventEnvelope`) и payload с версией схемы. В событиях только идентификаторы и время, без персональных данных: Kafka хранит сообщения неделями, и удалить из неё данные по запросу пациента нельзя.

## Рассмотренные варианты

- **Отправка в Kafka после коммита.** Теряет события при падении между шагами. Отклонено.
- **MassTransit / CAP.** Готовые outbox, но коммерческая лицензия у MassTransit и лишний слой абстракции. Отклонено.
- **CDC (Debezium) по WAL.** Без опроса и с минимальной задержкой, но отдельная инфраструктура (Kafka Connect). Для pet-проекта избыточно. Можно вернуться при росте нагрузки.
- **`LISTEN/NOTIFY` вместо опроса.** Меньше задержка, но уведомления теряются при разрыве соединения, так что опрос всё равно нужен. Отложено.

## Последствия

- Доставка **at-least-once**: падение между публикацией и отметкой даст повтор. Консьюмеры обязаны быть идемпотентными по `eventId` (inbox, фаза 5).
- Задержка публикации — до интервала опроса (500 мс).
- Сообщение, которое брокер отклоняет всегда (например, слишком большое), заблокирует события своего врача. Это видно по `attempts` и `last_error`; алерт появится в фазе 8.
- Новое доменное событие без отображения в контракт роняет сохранение с явной ошибкой, а не теряется молча.
